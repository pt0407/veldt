# Veldt v1.1+ Roadmap — post-v1 positioning

## Where Veldt stands vs. real languages (honest)

Veldt will not beat Python/JS/Ruby/Lua on ecosystem, performance, or
maturity — that's a multi-year, multi-decade fight. But there ARE
languages/tools it can plausibly beat within specific niches:

| target | why beatable | honest odds |
|---|---|---|
| **Awk** | text-munging DSL; Veldt has regex + dicts + comprehensions + real modules + HTTP/SQLite access Awk can't touch | high — for anything beyond one-liners |
| **jq (as a tool)** | complex multi-step JSON pipelines become unreadable in jq DSL; a Veldt script with dicts/comprehensions/imports is maintainable | high for multi-stage pipelines |
| **Fish scripting** | slow, weak data structures, no real module story; Veldt has real functions/structs/threads | high for >50-line scripts |
| **Tcl** | legacy embedder, weak ergonomics/data structures; Veldt wins on literally every language feature | high where Tcl still lives (EDA, legacy tooling) |
| **AutoHotkey-class automation** | AHK is Windows-bound + ugly; Veldt automation scripts (fs/exec/env/args) are portable | medium — loses on ecosystem |
| **Groovy/Bash for glue scripts** | slow JVM startup / no data structures; Veldt has instant start + real types | medium — Bash is too entrenched |
| **Babashka** | closest real competitor for "small capable scripting"; they win on perf (GraalVM) + ecosystem, we win on the garden | niche-only — PL hobbyists |

The one dimension where Veldt beats *everything* trivially: the garden.
No other language has persistent evolving function ecosystems. That is
the positioning — not "a faster X" but "a language whose code lives."

## Phase 7 — the honest algorithmic win ✅ (mechanical half done)

The garden still only produces *equivalent leaner* code, never a better
*algorithm*. This is the credibility gap. Operators that could find real
wins mechanically (no LLM needed):

- [x] **Dead-branch elimination**: `if`/`while` with const condition →
      splice taken arm / drop dead loop (`Mutation::DeadBranch` — both
      lanes landed; also removes `while false` loops)
- [x] **Loop-invariant hoisting**: `let x = <invariant>` inside `while` →
      hoisted before the loop (`Mutation::HoistInvariant` — both lanes)
- [x] **Early-exit insertion**: `while c { if c2 {return x} rest }` →
      `while c && !c2 {rest} if c2 {return x}` (devin — Mutation::EarlyExit)
- [x] **Constant expression folding across statements**: `let a = 2*3;
      return a` → `return 6` (devin — Mutation::ConstProp) + intra-expr
      literal folding (`Mutation::ConstFold` via const_eval — main lane)
- [ ] Benchmark target: seed `max_val(xs)` doing `xs.sort().reverse()[0]`
      (still needs a rewrite-rule mutation — mechanical ops remove waste
      but can't invent a different algorithm)
      and have the garden produce ANY lower-step equivalent — even if
      that's just a scan the seed family already contained, proving
      the selection machinery picks algorithmic winners.
- [ ] Then verify `veldt evolve --llm` end-to-end with a real key and
      publish the first genuinely-improved algorithm in the repo's
      history.

## Phase 11 — execution layer: bytecode VM → Cranelift JIT

The vision doc's first structural prerequisite. The tree-walker stays
as the semantic reference; a stack-based bytecode VM becomes the fast
executor, then a Cranelift tier JITs hot functions to native code.

- [x] `src/vm.rs` — bytecode format + compiler (Copy instrs, const pool,
      interned names, slot-indexed envs)
- [x] stack machine covering the language subset: arithmetic/logic/`??`/`in`,
      let/assign, if/while/for+break/continue, fn+`call_best`+`name#N`,
      closures, imports (`alias::name`), match, `?.`, slice, destructure,
      list comprehensions, field/struct ops, try/catch
- [x] `veldt run --vm` flag — same source, different engine
- [x] parity tests: `tests/vm_parity.rs` (8 tests) — identical variable
      state on both engines
- [x] step accounting preserved (max_steps counter on the VM)
- [x] benchmark: ≥10× achieved on dict_ops (32×) and recursive fib (88×);
      ~3× on numeric_loop/fn_calls — honest partial on the 10× target
- [x] Cranelift tier-2 JIT for hot garden variants — `src/jit.rs`,
      shared JitEngine, pure-int fns → native at ≥64 calls

Owner: main-side lane. All-new module; zero collision surface with
gardener's agent.rs/interpreter.rs work. **Status: SHIPPED** — bytecode
VM (full subset) + Cranelift tier-2 JIT with THREE signature modes:
int/float scalar for numeric fns, and a boxed-Value ABI
(fn(*mut JitRt, *const Value, i64) -> *mut Value) covering the ENTIRE
instruction set — strings, lists, dicts, structs, methods (incl
write-back), for-loops, index/slice, in, try/catch (compile-time
try-stack + take_err), and closures (env snapshot + call_closure).
garden --jit: 37/37 = 100% native — and now CORRECT, not just
compilable: a CallConv::SystemV bug emitted Unix-SysV code while
extern "C" callers use the host ABI (rcx vs rdi args on Windows),
so native calls read garbage regs and returned a stray register
boxed as Int — recursion fed it back into itself -> stack overflow.
Fixed with isa.default_call_conv(); fib(15)->610 under --vm, parity
suite green. Direct native calls between value-mode fns via a
shared-arena JitRt (one root arena per call tree). veldt test --vm
+ veldt fuzz --vm run trials/boundary corpus on the fast engine.
Honest perf: dict_ops 32x, recursive fib 88x, numeric_loop 3x,
fn_calls 3.6x — value-mode gain is modest (helpers do the work);
specialization (skip the helper for provable-int ops) is the next
honest win.

Asymptotic-evolution proof (mechanism-level, shipped):
mutate_binop can now produce + -> * (the operator that turns a
loop step geometric — i += k -> i *= k is O(n) -> O(log n) iteration
count), and asymptotic_proof::invariant_hoist_yields_asymptotic_
speedup demonstrates the headline claim directly: mutating an
O(n*len) body (a costly() inner loop inside an outer loop) with
HoistInvariant produces a variant that returns the SAME output at
>3x fewer interpreter steps. The remaining honest gap is an
end-to-end demo where `veldt evolve` *selects* the faster variant
in a real garden — measure_efficiency + eff_bonus exist, so the
selection machinery is in place; it needs a planted-workload
demonstration.

## Phase 12 — formal verification for canonical promotion

The vision doc's second prerequisite — SMT proofs gate Stage 2
(canonical) promotion instead of "passed the probe pool."

- [x] z3 crate integration — `veldt verify --exact`: bodies ->
      SMT formulas, solver.check(f(x)!=g(x)) — Unsat=proven,
      Sat=real counterexample. Scope: int/bool, straight-line
      + if/call; loops/match/strings bail to bounded.
- [x] `veldt verify <fn>` — bounded equivalence check: evaluates each
      variant on a bounded int domain and reports which agree with the
      fittest (honest middle tier: stronger than probes, weaker than SMT)
- [x] `veldt adopt <fn#N> --verify` — Canonical promotion gated on the
      bounded check; divergent variants stay at their trust tier with
      the counterexample printed
- [x] symbolic eval → SMT formulas (int/bool first) — shipped as
      `veldt verify --exact` (main lane): Unsat = PROVABLY EQUIVALENT,
      Sat = PROVABLY DIVERGENT + real counterexample, planted as a
      garden probe (`smt:cex#id` niche). Match arms expand via ite-
      chains. `veldt stats --exact` = SMT census across families.
      z3 is an optional cargo feature (`--features smt`) — bundled
      z3 needs a C++ toolchain + cmake.
- [x] `veldt adopt <fn#N> --exact` — Canonical promotion gated on Z3
      SMT proof (`Unsat` promotes; `Sat` prints counterexample and refuses)
- [x] document the honesty boundary: bounded-verified covers the
      domain, not the whole input space — documented in `docs/reference.md`

## Phase 14 — static diagnostics + live tooling (SHIPPED)

`veldt check --strict` grew from a stub into a real linter — ~91
warnings across six classes, all semantically grounded (few
false-positives by design; each batch verified against
examples/tictactoe.veldt):

- **real-bug**: call arity (f(x) where fn f wants N args — walks
  match patterns, test clauses, lambdas), let/param shadowing a
  defined fn, let/assign of a call whose fn never returns a value,
  unbound let self-read, assign-to-undeclared (scope-threaded),
  grow test calling a different fn, unreachable code after return
- **dead code**: bare-expression bodies, duplicate/unreachable match
  arms, empty-list/struct lets that never grow (stmt_grows sees
  append/push/index-assign through nested bodies), for over
  empty/descending iters, dead lets, unused params/imports
- **suspicious control flow**: loops without break/return/continue,
  while-call-cond never mutated, catch-only-print, body-only-prints
- **simplification**: compound-assign, bool-compare, x&&x/polarity/
  tautology conditions, duplicate let exprs, 1-element list literals
- **match hygiene**: non-exhaustive matches, patterns/scrutinees
  bound to literals/calls/binops/containers/aliases (incl. transitive)
- **property-only tests** — grow tests without expected values

Live tooling: `veldt check|test|fuzz|bench --watch` re-render on
file/garden mtime (mutation commands intentionally unwatched).
`veldt deps` = file-level import inspection. `check --json` for
machine consumption (IDE/Gardener wiring). Observability: fitness/
lifecycle/niche/turnover/workload/failure-mode sparks on stats,
garden --jit sig tags, evolve per-cycle fitness delta.

**Garden loop (shipped):** `check --garden [family]` lints variant
bodies via synthetic-wrap; `check --garden --fix` applies three
conservative mechanical repairs (dead-tail truncation, pure dead-let
removal, trailing-continue drop — semantics-preserving, verified by
re-trial); `stats --lint` is the warning census; `adopt --lint` gates
promotion; `veldt tend [family]` heals sick variants on demand;
evolution normalizes candidates pre-dedup and rejects mutants
introducing defect-class warnings (`[LINT]` events). `check -`
reads stdin for buffer pipes; `veldt lsp` publishes the same checks
as severity-2 diagnostics anchored to the enclosing fn; the agent
`lint`/`code health` intent reports code-health conversationally.
First garden-wide --fix run: 372 -> 85 warnings.

Remaining lint headroom is thin by design — next wins are
type-aware checks (needs inference) and repair passes for
semantic warnings (loop-no-exit, compound-assign shapes that
require proven intent)
(needs source spans, which the AST doesn't carry today).
